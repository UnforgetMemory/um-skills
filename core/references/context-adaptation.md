# 上下文自适应（L0 — 档位 + 波次迭代）

## 原则
- **步骤完整性优先**：L/M/H 只决定上下文管理策略，绝不删工程步骤
- 容量不足的唯一降级 = 波次切细（更多更小的波），不是跳过

## 档位自检（Phase 0，会话内一次，用户可显式覆盖）

| 决策点 | High（容量充足） | Medium | Lite（紧张） |
|--------|----------------|--------|-------------|
| 规则加载 | 全部相关 read | 仅当前波 read | 波更细 + 单波只读 1 个 |
| subagent | 可并行多开 | 1-2 个 | 少用/不用，主 agent 串行 |
| 报告 | 完整 | 精简 | 一行状态 + 证据位置 |
| 验证 | 全量 | 核心 | 最小（语法/静态） |

## 波次迭代模式（单兵作战 + 收缩结构）

```
1. 波次规划：流程按依赖切波，每波 = 可独立验证的子集
   W1(收集) → W2..Wn(各流程) → Wfinal(验证/报告)
2. 波内执行：只 read 当前波需要的 reference，其余不在上下文
   产出结构化证据（文件:行 / 命令输出）
3. 波间收缩：波完成 → 保留「波摘要 + 证据位置」
   细节 → 环境原生压缩（dsh-compaction 等）或疏散给 subagent 持有
4. 主 agent 上下文恒定 = 波次计划 + 当前波 + 各波摘要
```

## 防溢出
- 估算剩余容量 < 阈值 → 立即切 Lite 波次，不硬撑
- 溢出风险 > 引导完整性的损失 → 宁缺毋滥，保稳定性
