# 决策面板（L0 — 一次多问，禁止分轮）

## 机制
- 环境交互工具一次可传多个问题 + 结构化选项（GUI 渲染为按钮卡片）
- **禁止**把相关决策拆成多轮提问（每轮 = 一次 agent 调用 + 上下文往返）
- 依赖决策：预先确认意愿，条件执行（如"推送"= commit 成功后执行；失败 → 暂停回报，未经再次面板确认禁止自动重试）

## 确认效力（硬前置 · 协议见 prohibitions.md）

- 面板选项返回 = 唯一有效确认；未返回 → 对应执行 Phase **BLOCKED**，禁止继续
- 单次效力：每次确认仅覆盖当次内容与当次执行；内容变更或新一轮 → 重新展示 + 重新确认
- 效力层级：确认面板必须附带效力选项——「仅本次」（默认推荐，单次有效：内容变更/新一轮须重新确认）与「本会话允许」（仅豁免同动作类型的确认项，新决策项仍须提出；内容展示不豁免；范围沿用授权当轮选项，禁止扩大；仅限用户显式选择，可随时撤销，会话结束失效）
- 确认结果（面板编号 + 用户选项 + 效力层级）必须写入分册报告「人工确认记录」行
- 禁止推定：先前对话 / 任务文本中的「提交 / 推送 / 发布」字眼不是确认；禁止以「用户已要求」跳过面板

## 版本智能适配（不把全部选项端上来）

### 1. 版本源检测（官方优先）
按序：package.json → pyproject.toml → Cargo.toml → build.gradle(.kts) → pubspec.yaml → VERSION → 最近 git tag
无任何版本源 → 智能判断：库/发布物（有 exports/发布产物）→ 询问是否建立版本管理；纯脚本 → 默认无需，仅 [Unreleased]

### 2. 风格解析 → 只给匹配选项
| 现有风格 | 只展示 |
|---------|--------|
| SemVer（1.2.3） | major / minor / patch / 自定义输入 / skip |
| CalVer（YYYY.MM.DD） | 日期版本 / 自定义输入 / skip |
| 自定义 | 沿用 / 自定义输入 / skip |
| 无版本管理记录 | 建立版本管理（y/n）+ 初始版本建议 |

### 3. CalVer 格式链
```
基础      YYYY.MM.DD            → 2026.08.14
同日再发  +HHMM                 → 2026.08.14.1530
同日同刻  +HHMM + 随机二位数     → 2026.08.14.1530.42
```

## 面板模板（umcommit 示例）
```
Q1 版本升级：options=[与项目匹配的版本选项]（已计算目标版本并展示）
Q2 提交确认：options=[确认 N 个 commit, 修改意见]（已展示 COMMIT PLAN + 消息；修改意见 → 修订后重新面板确认）
Q3 推送意愿：options=[提交后推送, 仅本地提交]（条件执行）
Q4 确认效力：options=[仅本次, 本会话允许]（默认仅本次；本会话允许 = commit/push 免逐次确认，内容展示不豁免；会话结束失效）
```

## 面板模板（umrelease 示例）
```
Q1 版本确认：options=[与项目风格匹配的版本选项]
Q2 发布范围：options=[发布, 仅打 tag 不发布, 修改 Notes]（一次交互；决定 P5 tag 与 P7 发布是否执行；修改 Notes → 重做后重新面板确认）
Q3 确认效力：options=[仅本次, 本会话允许]（默认仅本次；本会话允许 = tag/发布免逐次确认，内容展示不豁免；会话结束失效）
```
