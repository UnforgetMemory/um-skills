# 决策面板（L0 — 一次多问，禁止分轮）

## 机制
- 环境交互工具一次可传多个问题 + 结构化选项（GUI 渲染为按钮卡片）
- **禁止**把相关决策拆成多轮提问（每轮 = 一次 agent 调用 + 上下文往返）
- 依赖决策：预先确认意愿，条件执行（如"推送"= commit 成功后执行，失败则暂停回报）

## 版本智能适配（不把全部选项端上来）

### 1. 版本源检测（官方优先）
按序：package.json → pyproject.toml → Cargo.toml → build.gradle(.kts) → pubspec.yaml → VERSION → 最近 git tag
无任何版本源 → 智能判断：库/发布物（有 exports/发布产物）→ 询问是否建立版本管理；纯脚本 → 默认无需，仅 [Unreleased]

### 2. 风格解析 → 只给匹配选项
| 现有风格 | 只展示 |
|---------|--------|
| SemVer（1.2.3） | major / minor / patch / 自定义输入 / skip |
| CalVer（YYYY.MM.DD） | 日期版本 / 自定义输入 / skip |
| 自定义 | 沿用 / 自定义输入 / skip |
| 无版本管理记录 | 建立版本管理（y/n）+ 初始版本建议 |

### 3. CalVer 格式链
```
基础      YYYY.MM.DD            → 2026.08.14
同日再发  +HHMM                 → 2026.08.14.1530
同日同刻  +HHMM + 随机二位数     → 2026.08.14.1530.42
```

## 面板模板（umcommit 示例）
```
Q1 版本升级：options=[与项目匹配的版本选项]（已计算目标版本并展示）
Q2 提交确认：options=[确认 N 个 commit, 修改意见]（已展示 COMMIT PLAN + 消息）
Q3 推送意愿：options=[提交后推送, 仅本地提交]（条件执行）
```
