# 破坏性操作门禁（D0-D3 分级）

> 配套 `prohibitions.md` 安全门禁 A-D：任何修改/创建/删除前先过 A-D，再按本文件分级执行。
> 分级按破坏性递增：D0 免确认白名单 < D1 覆盖写 < D2 文件删除 < D3 目录删除/历史破坏。
> 全级通用：每个修改/删除必须给出充分、简洁、明了的理由（做什么/为什么/影响），并标注可恢复性（可恢复 / 不可恢复）。

## 分级总表

| 级 | 定义 | 前置要求 |
|----|------|---------|
| D0 | 可重新生成产物删除（白名单） | 一次性列清单；免逐项确认 |
| D1 | 覆盖写（write/edit 已有文件） | read 原文 + 意图确认；git 可恢复 |
| D2 | 单文件/多文件删除（已跟踪） | 逐项清单 + 确认 + 恢复点 |
| D3 | 目录递归删除 / 未跟踪文件 / git 破坏命令 | 全量清单 + 可恢复性声明 + 恢复点 + 显式确认 |

## D0 免确认白名单（可重新生成）

判定标准：可由源码/包管理器/构建工具确定性重建；不含人工内容。
白名单外的路径一律不得套用 D0。

| 类 | 目录/文件 |
|----|-----------|
| 依赖安装 | `node_modules/` `.venv/` `venv/` `.gradle/` `.kotlin/` `.maven/` `.dart_tool/` `vendor/` |
| 构建产物 | `dist/` `build/` `out/` `target/` `.output/` `.next/` `.nuxt/` `.expo/` `__pycache__/` `*.pyc` `*.class` `*.o` `*.obj` |
| 缓存 | `.cache/` `.parcel-cache/` `.pytest_cache/` `.mypy_cache/` `.ruff_cache/` `.eslintcache` `.tsbuildinfo` |
| 测试产物 | `coverage/` `.coverage` `playwright-report/` `test-results/` `*.tmp` `*.log` |
| 会话临时 | `.um.agents/tmp/`（已 gitignore） |

规则：
1. D0 执行 = 一次性列出全部路径清单 → 直接删除，免逐项确认（仍须先过门禁 A-D）。
2. 白名单目录若被 git 跟踪或含人工修改 → 升 D2/D3。
3. 删除后如构建/测试需要，按需重建并验证。
4. IDE 配置（`.vscode/` `.idea/`）不在白名单——含人工配置，按 D2。
5. 锁文件（`package-lock.json` 等）禁止列入 D0。
6. 项目特有可再生成路径可追加到 `.um.agents/constraints/project-rules.md`，同样适用 D0。

## D1 覆盖写

1. 覆盖前必须 read 原文，明确旧值 → 新值。
2. 已跟踪文件 git 可恢复，但仍须：意图在已确认任务范围内，范围外先确认。
3. 禁止为通过测试/编译而删除或覆盖有效文件——修复代码，不删文件（见 review-cleanup.md）。

## D2 文件删除（已跟踪）

1. 逐项列出路径 + 理由。
2. 删除前建恢复点（recovery-points.md）：记录 HEAD 哈希，必要时 `git stash -u`。
3. 人工确认后执行；执行后回归验证（构建/测试）。

## D3 目录删除 / 未跟踪文件 / git 破坏命令

1. 目录删除前：递归列出全部受影响条目（含未跟踪文件），逐项声明可恢复性：
   - git 跟踪 → 可恢复（git restore / reflog）
   - 未跟踪 → 不可恢复 → 必须先备份到 `.um.agents/tmp/`
2. git 破坏命令列入：`git reset --hard` · `git push --force` · `git clean -fd` · `git checkout --`（丢弃改动）· 删除远端 tag/branch。
   这些命令**禁止自动执行**，仅用户显式命令才可执行；执行前必须记录恢复点。
3. 显式人工确认后才执行；禁止通配符盲删（未列清单即违规）。
4. 执行后立即验证：构建/测试/`git status`。

## 工作区外（OOB）操作

定义：操作目标位于 root 工作区之外（门禁 A 边界外：其他仓库、家目录、系统目录等）。

1. **默认 = 权限确认**：一律先 ask 用户确认，禁止自动执行。
2. **理由**：确认请求必须包含充分、简洁、明了的理由（做什么 / 为什么 / 影响面）。
3. **可恢复性提示**：必须标注
   - 可恢复：目标被 git 跟踪且可 `git restore`/reflog 找回，或已有恢复点；
   - **不可恢复**：未跟踪 / 无备份 / 无版本管理 → 明示「无可恢复」。
4. **git 方案推荐（可选，不替代确认）**：仅当同时满足
   - 目标在某 git 仓库内且被跟踪；
   - 目标是单文件或小体积目录（可快速恢复）。
   满足 → 在确认请求中附 git 恢复方案（见 recovery-points.md 恢复命令表）；不满足（大目录 / 非 git 文件）→ 不推荐 git 方案，仅权限确认。
5. 确认通过后才执行；执行后按对应 D 级验证。

## 证据输出

每项破坏性操作输出一行：
`D<级> <路径> — 清单/确认/恢复点/验证 四项齐全`
