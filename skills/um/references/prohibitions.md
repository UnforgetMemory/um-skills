# 禁令

违反以下任何一项都是**严重违规**，必须在 Review 中拦截。

## 架构与设计

| # | 禁止 | 原因 |
|---|-----------|--------|
| 1 | 用大规模重构代替局部修复 | 不必要风险；扩大变更范围 |
| 2 | 空抽象层（没有多个实现的接口） | 违反 YAGNI；认知负担 |
| 3 | 不必要的依赖 | 构建时间与维护成本 |
| 4 | 修改无关模块 | 超出范围；评审负担 |
| 5 | 为不存在的未来做泛化设计 | 违反 Evolution First |

## 执行与验证

| # | 禁止 | 原因 |
|---|-----------|--------|
| 6 | 未经验证就宣称"完成" | 违反验证阶段 |
| 7 | 跳过 Review 阶段 | 质量门禁不可绕过 |
| 8 | 降低测试标准以通过 CI | 测试是安全网，不是障碍 |
| 9 | 跳过回归验证 | 功能/性能回归必须检查 |

## 协作与变更

| # | 禁止 | 原因 |
|---|-----------|--------|
| 10 | 自动 git commit | 变更需要人工评审 |
| 11 | 自动 git push | 远程变更需要人工确认 |
| 12 | 自动发布 / 版本发布 | 发布由人工触发 |
| 13 | 多个 agent 同时修改同一文件 | 冲突；违反协作纪律 |
| 14 | 提交调试代码 / TODO / 死代码 | 工程卫生差 |

## 前置安全门禁（任何修改/删除操作之前）

任何修改/创建/删除之前，所有门禁必须通过。未满足时，该操作被禁止，直到用户明确允许。

| # | 门禁条件 | 未满足时 |
|---|----------------|----------|
| A | 工作目录在 git 仓库内（`git rev-parse --is-inside-work-tree`） | 阻止所有文件修改/创建/删除；提示用户；等待明确许可 |
| B | Git 仓库配置了远程（`git remote`） | 阻止修改/删除；报告缺少远程；等待 |
| C | 已配置 Git 身份（`user.name` / `user.email`） | 阻止修改/删除；报告缺少身份；等待 |

门禁顺序：先 `git rev-parse` → 失败则阻止；然后检查 `git remote` 和 `git config user.*`。任一门禁失败 → 询问用户"是否继续？"并仅在明确许可后继续。
