# uma 分析方法（L2 — 只读分析讲解）

## 1. 分析类型路由

| 类型 | 触发意图 | 产物 |
|------|---------|------|
| 结构地图 | 陌生项目快速上手 | 入口 → 模块 → 依赖关系图 |
| 区域深潜 | 理解某目录/子系统 | 职责 + 内部结构 + 关键路径 |
| 链路追踪 | 一条链路的来龙去脉 | 定义 → 调用 → 数据流逐跳 |
| 引用点 | 谁在用 / 被谁用 | 定义/实现/调用/注入清单 |
| 重构分析 | 这块代码值得改吗 | 问题 → 利弊 → 可选方向（不执行） |
| 跨语言启发 | 这设计在其他语言怎么做 | 目标语言惯用法对照 |

## 2. 事实采集（只读）

- 结构：入口文件（构建清单/包清单/启动点）→ 目录树 → 模块依赖（grep import/依赖声明）
- 链路：符号定义 → 调用点（grep 符号名）→ 数据流（参数/返回值/状态）
- 引用点：定义/实现/调用/注入四类，逐条 `文件:行`
- 未知 API/框架 → 查官方文档，禁止猜测

## 3. 分析解答规范

- 结论先行：先给答案，再给证据链
- 每条断言标 `Fact`（已验证）/ `Assumption`（推断）/ `Decision`（用户选择）
- 利弊分析：每个方案列收益/代价/风险，不替用户决策
- 改进方向：只描述方向与影响面，不写代码；落地 → 触发 umpp / umreview
- 学术风格：术语先定义，推理步骤可见，开放问题明示

## 4. 跨语言启发

- 用目标语言惯用法解释当前设计（如「这个 Singleton 在 Rust 里对应 OnceLock」）
- 只讲解概念映射，不产出目标语言代码
